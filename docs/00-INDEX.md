# 开发文档索引

本目录记录这个项目的**设计决策与开发过程**，让你在任何一台电脑上 clone 下来都能看到
「当时为什么这么改、改了什么、下一步该做什么」。

| 文档 | 作用 | 什么时候看 |
| --- | --- | --- |
| [DEVLOG.md](DEVLOG.md) | 变更日志：每次开发动了哪些文件、为什么 | 想知道「上次改了啥」 |
| [01-gap-analysis.md](01-gap-analysis.md) | 现状盘点 + 应用性缺口分析 | 想知道「现在缺什么」 |
| [02-design-learning-features.md](02-design-learning-features.md) | 代码学习能力的设计方案、trade-off、接口草图 | 动手前先读这个 |
| [03-implementation-checklist.md](03-implementation-checklist.md) | 分步实施清单 + 验收标准 + 自检题 | 动手时对着做 |

## 文档约定

1. **文档只记录「设计 + 为什么」，不贴成品实现代码。**
   这个仓库是用来练手的（见根目录 `CLAUDE.md` 学习模式），代码由我（项目作者）自己写；
   文档里出现的至多是**函数签名、数据结构、伪代码**，函数体留空。
2. 每次开发（包括 AI 协作的 session）都要在 `DEVLOG.md` 追加一条，写清
   **动机 / 改了哪些文件 / 留了什么坑**。
3. 设计文档里的方案一旦被实现或被否决，要回到文档里标注 `[已实现]` / `[已放弃: 原因]`，
   否则文档会变成谎言。
