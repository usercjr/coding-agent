# 现状盘点与「应用性」缺口分析

> 目标：让这个 agent 不只是「能替人写代码」，而是**能让人把代码学明白**。
> 本文回答两个问题：现在有什么？离「好用的代码学习工具」还差什么？

---

## 一、现有能力盘点

| 能力 | 实现位置 | 现状 | 对「学代码」的实际贡献 |
| --- | --- | --- | --- |
| 工具注册表 + 统一分发 | `agent/tools/base.py`、`agent/loop.py` | 完整 | 地基。加新教学工具不用动内核 ✅ |
| 6 大内置工具 | `agent/tools/` | 完整 | 能读能改，但语义全是「**替你做**」 |
| Skill 渐进加载 | `agent/tools/load_skill.py` | 完整 | 教学规范的载体 ✅ |
| 教学模式 | `skills/teaching/SKILL.md` + `/teach` | **纯 prompt** | 约束了「不许代写」，但**没有任何工具支撑** |
| Slash Command | `main.py` `COMMANDS` | 只有 `/review` 一个宏 | 入口层基本是空的 |
| Hook 事件总线 | `agent/hooks.py`、`agent/default_hooks.py` | 完整（5 层安全） | 目前只用于安全，**没用于教学** |
| 跨会话记忆 | `agent/tools/remember.py` → `memory.md` | 完整 | 只记「事实」，不记「学习状态」 |
| 子 agent / 并行 worktree | `agent/loop.py`、`agent/workdir.py` | 完整 | 目前只用于并行改代码，**教学场景零复用** |
| 评测闭环 | `eval/` | 完整 | 只量化「任务成功率」，**不量化教学质量** |

### 一句话结论

> **教学模式现在只有「嘴」，没有「手」，也没有「眼」。**
>
> - 嘴 = `skills/teaching/SKILL.md`，告诉模型要怎么说话；
> - 手 = 能产出**确定性事实**的教学工具（代码结构、调用链、出题、改坏代码）——**完全缺失**；
> - 眼 = 对「用户到底懂没懂」的度量与记录——**完全缺失**。

## 二、三个应用性缺口

### 缺口 1：讲解没有结构化素材，靠「整文件塞进上下文」

现在要讲一段代码，agent 只能 `read_file` 把整个文件读进来。后果：

- **上下文贵**：讲 `loop.py` 要烧掉 200 多行；要讲跨文件调用链就得读好几个文件。
- **容易幻觉**：模型会「看起来很懂」地说出一条根本不存在的调用关系。
- **讲不出全局**：新人学一个仓库最需要的是「从哪读起、谁调谁」，而这恰恰是**读单个文件得不到**的。

→ 需要一个能把代码**算成事实表**的工具（模块骨架 + 调用边 + 建议阅读顺序）。

### 缺口 2：检验不是强制发生的

`skills/teaching/SKILL.md` 第 6 条写了「每写完一块出 2-3 个检验题」，但：

- prompt 约束是**软的**，模型在长对话里会忘；
- 出完题就没了，**答得对不对没人判、没人记**；
- 用户自己也不知道「我哪几块是真懂、哪几块是蒙的」。

→ 需要把「出题 + 判定 + 记录掌握度」工具化，让它可触发、可验证、可统计。

### 缺口 3：学习是**无状态**的

每次 `python main.py` 都是从零开始。agent 不知道：

- 你已经学过哪些模块、哪些是自己写的；
- 你上次卡在哪、哪个概念反复出错；
- 哪些知识点到了该复习的时间。

`memory.md` 能记事实，但它是**扁平的一行行文本**，不足以支撑「掌握度 / 复习调度」这类带结构的状态。

→ 需要一份结构化的**学习状态**，以及读写它的工具。

## 三、缺口 → 方案的映射

| 缺口 | 对应方案（详见 [02-design-learning-features.md](02-design-learning-features.md)） |
| --- | --- |
| 1. 讲解没有结构化素材 | **S1 `codemap` 工具**（AST 抽骨架 + 调用边）、**S2 `/explain` 分层讲解** |
| 2. 检验不强制 | **S3 `/quiz` 出题 + 判定 + 掌握度记录**、**S6 教学质量评测** |
| 3. 学习无状态 | **S3 的掌握度文件**、**S5 间隔复习调度** |
| （额外杠杆）已有 worktree 没被教学复用 | **S4 `/breakit` 破坏式学习** |

## 四、一个值得记住的判断

这个项目最稀缺的不是「再加几个工具」，而是：

> **把已经造好的轮子（worktree 隔离、LLM-as-Judge、Hook 总线、记忆）复用到教学场景。**

S3 的判题直接复用 `eval/run_eval.py::check_judge`，S4 直接复用 `agent/loop.py::_run_in_worktree`。
同样的工作量，复用方案的收益和「简历可讲性」都高得多——因为它证明的是**架构设计**，不是堆功能。
